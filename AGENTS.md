# AGENTS.md — conventions for coding agents (and humans)

Commands, conventions, and stale-training-data traps. Rationale lives in `docs/adr/`.

## Toolchain

- **pnpm only** (`packageManager` pins `pnpm@11.10.0`). Use `pnpm dlx` / `pnpm exec`, never npm/npx. Node 24 via `.nvmrc` (fnm auto-switches).
- Postinstall build scripts are allowlisted in `pnpm-workspace.yaml` (`allowBuilds`: workerd, esbuild, …). If `pnpm install` reports newly blocked builds, add them there — don't run interactive `pnpm approve-builds`.
- `pnpm check` must pass; both `check` and `build` regenerate `worker-configuration.d.ts` (`wrangler types`) rather than validate it — its content legitimately varies with build state (wrangler adds a `mainModule` import only when `.svelte-kit/cloudflare/_worker.js` exists), so `--check` can never be stable across CI and local. The file is committed (IDE needs it), prettier- and eslint-ignored; don't fight small diffs in it.

## Svelte / TypeScript

- **Runes only** (`$state` / `$derived` / `$effect`); no legacy stores. Shared reactive state goes in `.svelte.ts` modules under `src/lib/state/`.
- mode-watcher 1.x: read `mode.current` (not the old `$mode` store); set via `setMode()` / `resetMode()`.
- TS is strict + extras; `exactOptionalPropertyTypes` is deliberately off (ADR 0003) — don't re-enable it.
- `checkJs` must also stay off: `worker-configuration.d.ts` imports the built worker entry, so after any build the JS bundle artifacts enter the TS program and would fail `pnpm check`.
- Navigation needs `resolve()` from `$app/paths` (eslint `svelte/no-navigation-without-resolve`); the rule is disabled only for the generic `ui/` primitives.
- Reactive collections use `SvelteMap`/`SvelteSet` from `svelte/reactivity` (eslint enforces it in `.svelte.ts`); a transient non-reactive `Set` still trips the rule, so avoid it — prefer `.clear()` + repopulate.

## Data layer (Phases 2–3)

- **The Y.Doc is the source of truth.** Three layers, one direction: `model/` = plain types + pure functions (no Yjs, no runes); `sync/` = the only place that (de)serialises a `Y.Map`; `state/` = the runes bridge that observes Yjs and projects into a `SvelteMap`. `sync/` must never import from `state/` or `components/`; `model/` has zero runtime deps.
- **Never mutate the projection directly.** UI writes go through `IssueStore.create/update/remove` → the CRDT → `observeDeep` → the projection. The `SvelteMap` is derived state, not a store.
- **Every write a person makes goes through `IssueStore.#write`.** Undo tracks only that origin, because "no origin" is not the same as "this visitor": Yjs tidies up after two peers format a Y.Text at once in a new local transaction with no origin, and a store tracking that gave a peer a way to push steps onto anyone's stack and wipe their redo. A store method that calls `sync/` directly still writes, but it cannot be undone.
- **Issue field writes stay in a `doc.transact()`** so one issue change is one observer batch. Order keys come from `fractional-indexing` (`generateKeyBetween`) — append with `nextOrderKey`; never reuse a key.
- **A value under `issues` is not necessarily an issue.** Any link-holder can store a string, a `Y.Text` or anything else there, and a `Y.Map`'s type parameter is only a cast, so `getIssuesMap` returns `Y.Map<unknown>` and reads go through `getYIssue` / `yIssues` (`sync/doc.ts`). Don't test truthiness or look for `.get`: `null` is falsy, and `Y.Array`, `Y.XmlFragment` and a sub-document all have a `.get` that reads back a ghost row which only throws when edited. An observer must ask what the entry is _now_ rather than trust `change.action`, because last-writer-wins can turn an issue into junk with an `update`. Junk stays in the document and is ignored; removing it would be a write nobody asked for.
- **A key under `issues` is not necessarily an id.** A `Y.Map` key is a peer's string, and it becomes `issue.id` and then a link: `../issues?ws=…` is a row that moves whoever clicks it into another workspace, and `''` or `/x` make `resolve()` throw while the list renders. `getYIssue` / `yIssues` only accept a key that passes `isIssueId`, the lowercase shape of `crypto.randomUUID()`, so never mint an id any other way. A test writing to a literal key like `'junk'` is now turned away for the key and proves nothing about the value, so give it a UUID. `resolve('/issues/[id]', …)` pastes its parameter in unencoded, so pass `issueIdParam(id)` rather than the bare id.
- **A string in `order` is not necessarily an order key.** `generateKeyBetween` throws on a bound like `'~'`, which would stop everyone creating issues, and it accepts `'a0.'` or `'aé'` and returns garbage, so "see if it throws" is no validator. Read the field through `readOrder` (`sync/issues.ts`), which maps whatever fails `isOrderKey` to `''` for `planRepairs` to rekey on the next move; a read never writes. Don't cap the length: real keys grow with each drop into one slot. Mint through `sync/order.ts` rather than the library, which can return the one key it refuses (`'A'` + 26 zeros) and overflows the stack on a long run of `z`s in a valid key, which only Firefox reports as an `InternalError` rather than a `RangeError`, in a browser the test suite doesn't run.
- **A number in `createdAt` is not necessarily a time.** `new Date(1e300).toISOString()` throws, and it runs while the editor renders, so a peer could make any issue fail on every open for everyone. `patchIssue` never writes `createdAt`, so no edit clears it. Read times through `readTime` (`sync/issues.ts`), which falls back for anything a `Date` can't hold; a read never writes, so the bad value stays stored, and `updatedAt` is replaced by the next edit.
- **An array in `labels` is not necessarily a set.** The UI dedupes what it writes, but a peer's array arrives as sent, and the views key their badges by the text, so a repeat throws `each_key_duplicate` in production too. `readLabels` keeps the first of each and never writes: saving the deduped value compares equal, so the repeat stays stored until the labels really change. It compares raw strings, which matches `parseLabels` on case but not on whitespace: `' bug'` and `'bug'` read as two labels, which is safe because they are two keys, and the next real edit through `parseLabels` collapses them. Any new `{#each}` keyed on a peer's string needs the same guarantee from its projection, as `Presence` gives for `userId`.
- **A peer can nest types deeper than the stack goes.** `cur.set('n', new Y.Map())` in a loop costs about 12 bytes a level and integrates silently, and stock Yjs deletes and collects a type's contents recursively. Past about 2,500 levels Delete threw halfway, the half-finished update threw out of `Y.applyUpdate` on every other replica, and the next load overflowed inside y-indexeddb, which cannot report it, so the visitor stayed on the skeleton. No check on a read can stop this, because a peer can send the tree and its delete set in one update, and that overflows before any code here runs. So `patches/yjs@13.6.31.patch`, which pnpm applies everywhere including the relay, makes those two walks iterative; `sync/deep-nesting.test.ts` fails without it. `redoItem` is iterative for the same reason, and a test of undo has to build its chain with two clients (`splitChain`), because one client's chain is redone parent first and never recursed. Redo the patch when bumping `yjs`. The rest of Yjs's recursive API still overflows, so never call `toJSON()` or `clone()` on anything a peer wrote.
- **A peer can nest a plain value deeper than the stack goes too**, for two bytes a level and with no type involved. Decoding and encoding a value each recurse, and they give out at different depths: `'['.repeat(n) + '{"toJSON":1}' + ']'.repeat(n)` passes `JSON.parse` and overflows `JSON.stringify`, which ran inside the cleanup after every transaction. That cleanup never finished, so the document kept taking writes while no observer or `update` fired again, in every tab that received it and every tab that loaded it from the relay's snapshot. So the patch's decoders read any value past `MAX_VALUE_DEPTH` as `null`, on every replica alike, and a throw during cleanup can no longer wedge a document. The limit is a fixed number on purpose: "whatever this stack can take" differs between the relay and a browser, and a value only one of them can read is how a workspace stops loading. Malformed JSON still throws, because it does so everywhere, so the relay refuses it and nobody stores it. Exercise this with `handWrittenItem` (`sync/junk-entries.fixture.ts`), since a patched sender cleans its own value up before it leaves.
- **A struct can claim to take up no clock.** A GC of length 0 is an 8-byte update, an item can carry no content at all, stock Yjs integrates both, and the rest of it assumes every struct is at least one long. An empty GC became a delete-set entry of length 0, which threw in every reader after its structs had landed: y-protocols only logs that, so the page looked synced, but the relay's `decodeSnapshot` caught it and woke with an empty workspace, and a compacted y-indexeddb row left the visitor on the skeleton. Any empty struct after a normal one sent `findIndexSS` to a NaN index on every encode, so the room stopped answering and saving. The patch's `readClientsStructRefs` drops them and `readAndApplyDeleteSet` skips an empty range. They are dropped rather than refused because old rows and snapshots hold them, and refusing one of those refuses the whole workspace; `sync/empty-structs.test.ts` fails without it.
- **A sub-document's options are a peer's to fill in.** Stock Yjs spreads them over the arguments of `new Doc`, so `{ guid: null }` replaced the guid the item had just read, and the item integrated and then threw on every encode, which is everything a relay does: no sync step 2 for anyone, no save, and writes lost once the object is evicted. The patch's `createDocFromOpts` reads `gc`, `autoLoad` and `meta`, the three things a real sub-document writes, and nothing else.
- **Never read `event.path` in an observer.** It walks to the observed type each time, and a peer can raise one event per level of a deep chain for a few bytes each, so reading it for every event is at least quadratic in something the peer picks. That is how a 168 KB update stalled every open tab for 18 s, with stock Yjs filing each event under every ancestor on top, which is what ran the relay out of memory. The patch files events only under types with a deep observer and sorts without computing paths; `touchedEntries` (`sync/doc.ts`) names each issue a batch touched, once, without paths either. Anything new that walks up from an event's target should remember what it has passed.
- **Persistence attaches synchronously** (static `y-indexeddb` import, browser-guarded) — a dynamic import reintroduces a lost-write window (see the comment in `persistence.ts`).

## UI (Phase 4)

- **The create dialog and the `c` shortcut live in the root layout** so "New issue" works from the list, the board and the command menu alike. When opening it from another dialog (the command palette), `await tick()` first, or the closing dialog's focus restore fires inside the new one's focus scope.
- **Issue components take `store` as a prop**; only routes call `getIssueStore()`. That is what lets browser-mode tests construct a throwaway `new IssueStore('test-<uuid>')` per test instead of sharing the session singleton.
- **Enum presentation lives in `components/issues/meta.ts`** (`STATUS_UI` / `PRIORITY_UI`: icon + colour). `model/issue.ts` owns labels and ranks only — it must keep zero runtime deps.
- **Those colours are per-theme on purpose** — a light step with a `dark:` `-500` override, not one shared `-500`. Rows and board cards render the badges icon-only, so the icon _is_ the information and has to clear WCAG 1.4.11's 3:1; the stock `-500` steps reach 2.15–2.89:1 on white. `meta.test.ts` recomputes every ratio from the installed `tailwindcss/theme.css` and `layout.css` rather than trusting a checked-in number, so collapsing them back to one step fails the suite.
- **The detail sheet is a route**, `/issues/[id]`, and the list lives in `issues/+layout.svelte` so it stays mounted behind the sheet. Close with `goto(resolve('/issues'), { replaceState: true, keepFocus: true, noScroll: true })`. `replaceState` stops Back from reopening the sheet; `keepFocus` only stops SvelteKit resetting focus to `<body>` — it restores nothing, because a route-as-sheet has no `Sheet.Trigger` for bits-ui's focus scope to return to. Putting focus back is `issues/+layout.svelte`'s `afterNavigate`, which targets `[data-issue-link=…]` and falls back to "New issue" only when that row is genuinely gone (the delete case). Read the arrived-at id from `page.params`, never the callback's `to.params`: on the initial load SvelteKit builds that object from pre-initialisation state, so `to.params` is `{}` on every cold deep link.
- **A view that renders records sits inside `ViewBoundary`** (`shell/view-boundary.svelte`), so a render bug costs that view and not the page; without one, a throw escapes the flush and every later update stops. In the sheet it goes around the editor alone, inside `{#key issue.id}`: the dialog keeps its name and focus trap, Delete stays reachable as the way out of a record that cannot render, and another issue doesn't inherit the failure. Keep `<main>` outside.
- **The layout preloads the detail chunk** (`preloadCode('/issues/*')` on mount). Without it the first navigation to an issue after going offline has no code to fetch and lands on an error page.
- **Editable fields use a nullable draft**: `null` means "not editing" and the input shows the live CRDT value, so remote changes flow through. The first keystroke sets the draft; commit writes it and returns to `null`. No `$effect` — drafts are set from DOM events only.
- **Drafts live in a keyed child component** (`issue-editor.svelte` inside `{#key issue.id}`). `{#key}` re-creates DOM but _not_ the enclosing component's `$state`, so drafts declared one level up leak between issues. Same reason the create form is a child of `Dialog.Content`, which bits-ui unmounts on close. The child's `issue` prop is still a live getter: during teardown, which is when blur and `onDestroy` flush a draft, it is already undefined or the next issue, so writes go by the `id` the editor captured when it was created.
- **`patchIssue` owns the write invariants**, not the UI: unchanged fields are dropped (a re-selected status must not bump `updatedAt` or reach the relay), and a blank title is ignored (`readIssue` only defaults a _missing_ title, so a stored `''` would render forever).
- **Icon-only controls must name their value** — `aria-label="Status: Backlog"`, not "Change status" — and `<Kbd>` inside a button needs `aria-hidden="true"` or it pollutes the accessible name.
- bits-ui notes: `AlertDialog.Action` does **not** close its dialog (manage `open` yourself); menu options are `menuitemradio`, not `menuitem`; a Sheet/Dialog needs a `Title` in _every_ branch or it has no accessible name.

## Relay (Phase 9)

- **The relay is its own workspace package** (`workers/relay`), with its own `wrangler.jsonc`, `tsconfig.json` (standalone — the app's pulls in the DOM lib and the app worker's `Env`) and CI steps. The root `pnpm check` and dry-run never touch it, so it has its own `check` and `dry-run` scripts and CI runs both.
- **The party name is the Durable Object binding name, kebab-cased.** Binding `YDocRoom` ⇒ `/parties/y-doc-room/:room`, and the client must pass `party: RELAY_PARTY`; the provider's default (`main`) is answered with HTTP 400. Rename one and you must rename the other in the same commit.
- **`routePartykitRequest` is async.** `routePartykitRequest(req, env) ?? fallback` is dead code — a Promise is never nullish — and returning it unawaited resolves to `null`, which workerd rejects. Await it, and keep the `satisfies ExportedHandler<Env>` that catches this at compile time.
- **The provider is the default export of `y-partyserver/provider`**, not a named one, and `partysocket` has no Yjs provider despite what older notes said.
- **`PUBLIC_RELAY_HOST` is `host[:port]`, read at build time** through `import.meta.env` (with `envPrefix` widened in `vite.config.ts`). `$env/static/public` hard-fails when unset, and `$env/dynamic/public` does not resolve in browser-mode unit tests. The port matters locally: the provider only picks `ws://` for hosts it recognises as local.
- **Status needs three events, not one.** `status` alone never reports a relay that was never reachable, so `connection-close` and `connection-error` also map to offline. `connected` fires when the socket opens, _before_ state has been exchanged — gate on `synced` for anything that needs the data.
- **Nothing may escape `onSave`.** y-partyserver subscribes to the document's `update` event and swallows a rejected `onSave` into a `console.error` (`y-partyserver/dist/server/index.js`, ~185-195) — no hook, no event, no client signal. The room then relays in memory while silently not persisting, and the next hibernation eviction loses everything since the last good write. `onSave` therefore checks the encoded size before writing and catches every write error itself, so that swallow is unreachable ([ADR 0010](docs/adr/0010-relay-snapshot-durability.md)).
- **A snapshot over ~1.9 MB is not written at all.** Cloudflare caps a string/BLOB/row at 2 MB and the cap is not plan-split, so no upgrade removes it. That is roughly 3,000-6,000 never-edited issues (`bytes ≈ 320 + descriptionLength` per issue, flat from 100 to 40,000). `store.seed(7000)` and above can therefore never be persisted by a relay — a benchmark path, not a demo one: `seed(n)` has no non-test callers and the Phase 12 button is `seedDemo()`, 14 issues.
- **`broadcastCustomMessage` only reaches sockets open at the instant it fires** (`dist/server/index.js`, ~243-262). Any room-level state a client must know is therefore pushed again from `onConnect`, after `super.onConnect` — which is synchronous, so the override must not be `async`. Without that, a reload or anyone arriving after the room hibernated sees a healthy UI.
- **Snapshot size and wake cost are different axes; guard both.** `Y.applyUpdate` on a cold wake costs ~0.5-0.7 microseconds per Yjs struct (ten per issue) and is independent of the byte count, so the 1.9 MB check cannot see it: 3,000 empty-description issues is 880 KB and ~18 ms, while 1,315 long-description issues is 1.96 MB and ~6 ms. `countStructs` reads the state vector rather than counting issues, so the relay still knows nothing of the app's schema and churn residue is included. Log-only — the CPU limit it guards against is undocumented for free-plan Durable Objects and unenforced locally (ADR 0010).
- **Persistence state is edge-triggered and latches.** A failing room announces once and then stays silent; the silence guard tests `state !== 'ok'`, not `=== 'degraded'`, because `onLoad` re-derives a stored failure as `'stale'` on _every_ hibernation wake and a narrower guard turns each wake into a fresh transition — thousands of row writes and log lines a day, and a dismissed banner that keeps returning. The notice's `at` is the stored timestamp, never `Date.now()`, for the same reason.
- **Teardown order: relay, then persistence, then the doc.** The provider does not detach on `doc.destroy()`, so a socket left open would apply an inbound sync message to a destroyed document.
- **Every e2e gets its own workspace** (`e2e/fixtures.ts`). A shared relay room otherwise leaks state between tests and across local runs, since the room's storage outlives the process.
- Playwright runs two servers; `use.baseURL` must be set explicitly, because Playwright only infers it from a _single_ `webServer` object. `unrouteAll()` does not remove `routeWebSocket()` routes — switch such a handler with a flag instead.

## Search (Phase 8)

- **Search runs in a module Web Worker** (`search/`), reached only through `new URL('./worker.ts', import.meta.url)` so FlexSearch and the embedding library never enter the server bundle. `vite.config.ts` sets `worker: { format: 'es' }` — the default `iife` cannot code-split a worker and silently inlines dynamic imports, which would ship the embedding library to every visitor.
- **FlexSearch 0.8 traps**, all of them load-bearing ([ADR 0006](docs/adr/0006-search-flexsearch-lexical-with-optional-local-embeddings.md)): `limit` is per _field_, so merge and slice; the document generic rejects an `interface` (use a `type` alias); ids are `string | number`; and title and description must be indexed as one combined field or a query whose words span both returns nothing. Keep all of this behind `search/lexical.ts`.
- **The worker starts at app load**, not on first search — its chunk is fetched when constructed, and an offline user could never fetch it.
- **Query ids are minted on the client** and bumped on every call including a clear, so a slow reply can never repopulate a list the user emptied. Results are ids; resolve them through `store.get(id)` so an edited or deleted issue is never rendered from a stale snapshot.
- **The index follows the CRDT through `IssueStore.onChange`**, which emits one delta per observer batch and a `reset` after the post-load rebuild (that rebuild fires no Y events, so a listener watching only deltas would never see the issues already in the document).
- **Embedding must yield.** ONNX inference is synchronous on its thread; embed in small batches, hand back the message queue between them, drop a document's vector when its text changes, and abandon a batch whose generation counter moved. Only report `hybrid` when every document has a current vector.
- **The palette does its own filtering** (`shouldFilter={false}` plus bits-ui's `computeCommandScore`): bits-ui otherwise scores items against the query and hides the rest, which deletes description-only and semantic matches. Issue items are keyed `issue:<id>`, never by title.
- **The model and the ONNX runtime are self-hosted** ([ADR 0009](docs/adr/0009-self-host-the-embedding-model-and-onnx-runtime.md)): `scripts/fetch-search-assets.mjs` vendors both into `static/models/` and `static/ort/` (gitignored, ~46 MB — run `pnpm fetch:search-assets` once, and CI does the same, cached by model version), and `search/worker.ts` sets `env.allowRemoteModels = false` so a missing local file fails loudly into the lexical-only path rather than silently reaching Hugging Face or jsDelivr. This is what makes the e2e path safe to exercise automatically now — `search.e2e.ts`'s self-host test watches for exactly those two hosts and asserts zero requests, so a regression here fails CI rather than showing up as a slow surprise mid-demo.
- transformers.js's `progress_callback` reports **0–100**, not 0–1 (`hub/utils.js`'s `readResponse`: `progress = (loaded / total) * 100`) — passed straight through this showed "10000%" partway through a real load. `warm()` divides by 100 before this module's own `status()`, whose contract (`client.svelte.ts`) is documented as 0–1.
- **`warm()` retries a transient failure** (2 attempts, 800ms apart) before reporting `'failed'` — fetching ~46 MB over one connection has room to fail for reasons that have nothing to do with self-hosting, and a single blip used to be permanent (nothing called `warm()` again). The palette's "Try again" button and this internal retry share the same call, since `warm()`'s guard (`semantic === 'loading' || 'ready'`) does not block re-entry from `'failed'`.

## Keyboard (Phase 7)

- **Every shortcut is declared in `keyboard/registry.svelte.ts`**, and the root layout owns the single `keydown` listener. The palette and the `?` help sheet render the registry, so a command and its key cannot disagree.
- **Never register `Enter` or the arrow keys globally.** `handle` calls `preventDefault` on a match, and at document level that kills button activation, link navigation and form submission across the whole app. Cursor keys belong to the widget that has focus — the list handles its own arrows, and Enter is plain link activation.
- **Chords match the character the keyboard produces** (`event.key`), never `event.code`. Shift is ignored for punctuation, because `?` is Shift+/ on a US layout and unshifted elsewhere. Note that Playwright's `press('Shift+/')` sends `key: '/'` while a real keyboard sends `?` — write `press('?')`.
- **A shortcut that must work inside an overlay needs both opt-ins.** `⌘K` lands on the palette's own combobox input inside a dialog, so `allowInInput` alone would make it open-only. The palette also sets `vimBindings={false}`: bits-ui's Command reads Ctrl+K as "previous item" and prevents the default.
- **`Command.Viewport` is required** inside `Command.List`, or `Command.Input` never gets `aria-controls`/`aria-activedescendant` and the highlighted item is not announced.
- **Suspend the registry while another widget owns the keyboard** (`shortcuts.setSuspended`). The board does this during a drag, and clears it on destroy — a stranded suspension kills every shortcut app-wide.
- **The list cursor is roving focus**, not `aria-selected` (invalid on `listitem`, and virtua owns the `<ul>`). Moving the cursor moves real focus so screen readers announce the row; pin the cursor's index with virtua's `keepMounted` or focus cannot land on a row outside the rendered window.
- **A row is a composite widget, so the list has exactly one tab stop.** Up/Down and `j`/`k` move between rows and always land on the row's _link_ — Enter has to be ordinary link activation. Left/Right walk the cursor row's status picker, link and priority picker. The pickers are `tabindex="-1"` in every row, the cursor row's link is the only `0`; before that, Tab walked every rendered row three times and entered at row 1's Status button.
  - **Derive `keepMounted` from whichever index is tabbable**, not from `selectedId`. They were computed separately once, so with no cursor placed the fallback row was tabbable but not pinned — scrolling away from the top left the list with _zero_ tab stops and no keyboard way in at all.
  - **Never mirror focus into state.** Read `document.activeElement` at the moment of a move. A remembered "column" written from an arbitrary `focusin` survives a mouse click on a picker, after which `j` moved down a row and left focus on that row's picker, so Enter opened a dropdown instead of the issue.
  - **A move reads its origin from focus, but moves focus a frame later**, so a second move arriving before the paint must fall back to the index rather than re-reading a stale `activeElement`. Key auto-repeat (15–30 ms against a 16.7 ms frame) is exactly this case: without the guard, holding `j` advanced one row in ten.
- Single-letter shortcuts are correctly inert while typing, so any text field the keyboard can get stuck in needs an escape hatch (the quick-add field blurs on Escape).

## Virtualization (Phase 6)

- **The issue list is virtualized with `virtua/svelte`'s `Virtualizer`** ([ADR 0005](docs/adr/0005-virtual-list-virtua-over-tanstack-and-svelte-virtuallists.md)) — not `VList`, because only `Virtualizer` takes `as` / `item`, which keeps the rows a real `<ul>`/`<li>` for assistive tech and for every `listitem` locator in the tests.
- **`issue-row.svelte` renders the row's contents, not the `<li>`.** virtua owns the item element so it can position and measure it, and absolutely-positioned items mean parent-based styling (`divide-y`) does not apply — per-item borders come from `itemProps`.
- **The virtualizer sizes itself from its direct parent**, so that parent needs a real height, and so does everything above it. The root layout fixes the shell at `h-svh`, because the provider's `min-h-svh` lets the page grow to fit and virtua then mounts every row, which only `e2e/list-window.e2e.ts` can see. The issues layout gives the list `min-h-64 flex-1`, so `<main>` scrolls on a screen too short for it. In a browser test, mount into a host with an explicit height **and import `routes/layout.css`**, or Tailwind is absent, the container has no height, and the list renders every row while appearing to pass.
- **Do not virtualize the board.** svelte-dnd-action indexes the drop zone's direct children positionally, so a rendered window would hide the rest of the column from the drag machinery. Columns are capped at `BOARD_COLUMN_LIMIT` instead, and the drop handler appends the ids behind the cap so a drop at the bottom of a capped column still sorts correctly.
- **Measure before optimising here.** At 10k the query index costs 2 ms and a single edit 0.7 ms; the DOM was the whole problem. `store.seed(n)` bulk-creates issues in one transaction for benchmarks (and, from Phase 12, demo data).
- Virtualized lists make Chromium emit `ResizeObserver loop completed with undelivered notifications`. It is benign — the browser has already recovered, and the real app logs nothing — but Vitest's error catcher surfaces it as an unhandled error in browser-mode output. It does not fail the run; ignore it.

## Board & ordering (Phase 5)

- **Order-key maths lives in `sync/order.ts`**, not `model/` (it needs `fractional-indexing`, and `model/` keeps zero runtime deps). Generated keys carry a random suffix so two replicas cannot mint the same key; `planRepairs` heals equal or blank keys that already exist, rewriting only the offending run.
- **Never call `generateKeyBetween` directly from UI or board code.** It throws when its bounds are equal, and a blank `order` (which `readIssue` produces for a missing field) crashes it with a `TypeError`. Go through `appendOrderKey` / `orderKeyBetween` / `moveIssue`, which normalise both.
- **`moveIssue` takes the target column's ids in their new order** and does all the key work: it excludes the moved card before repairing (its key is the one deliberately out of place), reads neighbours _after_ repairs, and writes repairs plus the move in one transaction. A pure reorder does not bump `updatedAt`; a status change does.
- **A drag that changes nothing must write nothing.** Jitter means a recomputed key always differs from the stored one, so the guard asks whether the existing key still sorts into the new slot — never whether the strings match.
- svelte-dnd-action facts that are not in its docs, all load-bearing (see `components/issues/board-drag.ts`):
  - A **keyboard drop** arrives as `consider` with trigger `dragStopped` and sends **no** `finalize`. Handling only `finalize` leaves the column frozen on a stale preview.
  - Every **arrow press** fires a full `finalize` mid-drag. Commit on `source === 'pointer'`, or on the `dragStopped` consider — not on every finalize.
  - Releasing outside every column still fires `finalize`, with `droppedOutsideOfAny`. Write nothing.
  - The zone's **direct children must be exactly the items**: the library indexes `node.children` positionally, makes each a draggable, and reads announcements from that element's `aria-label`. No wrappers (an `animate:flip` wrapper silently becomes the card), no empty-state placeholder inside the zone.
  - **Cards must contain nothing focusable.** Only direct children leave the tab order during a drag, and tabbing onto a column is the only way to move a card between columns.
  - Pass `zoneTabIndex: -1`, label the zone and each card with `aria-label`, and restore focus after a keyboard drop — the library leaves it on `<body>`.
  - **`delayTouchStart` is mandatory.** Without it the library calls `preventDefault()` on every `touchstart` that lands on a card, and cards cover nearly the whole column — so a phone cannot scroll the board at all. `true` picks the library's 80 ms, which is too short to read a card before deciding; the board passes `TOUCH_DRAG_DELAY_MS`.
  - **Setting a delay breaks tap-to-open, in both directions.** Under the delay the library synthesises its own click on `touchend` (`handleFalseAlarm`) _and_ the browser fires its compatibility click, so an activation handler must be idempotent. Past the delay `handleDragStart` unregisters `handleFalseAlarm` and `handleDrop` synthesises nothing, so a press-hold-release produces **no** click at all — the board recognises that tap itself, on a window `touchend`, gated on distance moved.
- **Drag previews live on the board page, not per column.** A drag ends untidily in the columns it merely passed through, so any ending clears every preview.
- Test drags with the **keyboard**; pointer drop detection polls on a 200 ms timer and animates before reporting.

## Styling

- Tailwind **v4 CSS-first**: there is no `tailwind.config.js` and never will be. Theme lives in `src/routes/layout.css` (oklch variables). Never delete the `@custom-variant dark (&:is(.dark *));` line — it is class-based dark mode.
- shadcn-svelte components in `src/lib/components/ui/` are **owned code** — edit them. Add new ones with `pnpm exec shadcn-svelte add <name>`, then run `pnpm format` (generated code fails `prettier --check`).
- **Four files deliberately differ from what the generator emits, and re-running it reintroduces a real accessibility failure.** Each carries an explaining comment in place; this is the list to check before regenerating.
  - `ui/sidebar/sidebar-inset.svelte` renders a `<div>`, not upstream's `<main>` — the inset wraps the app header as well as the page, so a `<main>` there forces either two main landmarks or a banner nested inside main.
  - `ui/button/button.svelte` uses solid `focus-visible:ring-ring` at `ring-2`. Stock `ring-ring/50` blends to 1.54:1 against white and cannot be rescued by darkening the token (2.32:1 even at `oklch(0.45)`).
  - `ui/sidebar/sidebar-menu-button.svelte` sets `type="button"` on its own element, because the props type is `HTMLAttributes<HTMLButtonElement>` and has no `type` key for a caller to pass.
  - `ui/command/command-dialog.svelte` nests `Dialog.Header` _inside_ `Dialog.Content`. As a sibling it is not gated on `open`, so a level-2 heading and the palette's description rendered into every page ahead of its own `<h1>`.
- **The shell's landmark contract**: the root layout owns the one `<main id="main-content" tabindex="-1">` (the `tabindex` is what makes the skip link move focus rather than only scroll), `app-sidebar.svelte` owns the app's only `<nav>`, and the skip link must stay ahead of `<AppSidebar />` inside `Sidebar.Provider` — inside `Sidebar.Inset` it renders after the sidebar and skips nothing. `e2e/a11y-shell.e2e.ts` is the guard.
- **`prefers-reduced-motion` is honoured globally in `layout.css`, but that rule cannot reach `animate:flip`**, which is JS-driven. The board reads `prefersReducedMotion` from `svelte/motion` (SSR-safe) and passes `flipDurationMs: 0`.
- Icons: `@lucide/svelte` (deep imports: `@lucide/svelte/icons/x`). Not `lucide-svelte`, not `cmdk-sv`, not `tailwindcss-animate` — all obsolete.

## Tests

- Vitest browser locators are `getByLabelText` / `getByPlaceholder` (Playwright's are `getByLabel` / `getByPlaceholder`) — chaining `getByLabel` off a Vitest locator throws at runtime, not at typecheck.
- `src/**/*.test.ts` → Vitest node project. `src/**/*.svelte.test.ts` → Vitest browser mode (needs `pnpm exec playwright install chromium`). `e2e/*.e2e.ts` → Playwright, whose webServer runs the **built worker under workerd** (`pnpm build && pnpm preview`, port 4173) — not vite preview.
- **`test.use({ reducedMotion })` is inert here — do not write a test that depends on it.** Measured with Playwright 1.61.1 and this config: at module scope, at describe scope, with and without this repo's `context` fixture, and on a freshly opened page from the same context, `matchMedia('(prefers-reduced-motion: reduce)').matches` stays `false`. `page.emulateMedia({ reducedMotion: 'reduce' })` works immediately. The failure mode is silent — the test passes while asserting the default preference twice — so `e2e/reduced-motion.e2e.ts` asserts the emulation took hold before asserting anything else, and any new motion test should do the same. The same trap voided an earlier A/B in this repo that tried to blame an e2e flake on the reduced-motion rule: both arms were the same arm.
- **Reloading straight after a local write can lose it.** y-indexeddb stores each update in a fire-and-forget IndexedDB transaction, and a navigation that commits first aborts it, so the reloaded page never had the write — and offline, nothing ever sends it. An e2e that writes and then reloads, cold-loads with `page.goto`, or closes the page calls `waitForCommitAbove` (`e2e/fixtures.ts`) first, baselined just before the write and after the page shows its IndexedDB load (its empty state or its list). It polls with `expect.poll` because `page.waitForFunction` does not: handed a predicate that returns a promise, it resolves after one call with whatever the promise settles to, `false` included.
- **`pnpm ci:local` (`scripts/ci-local.sh`) mirrors `.github/workflows/ci.yml` step for step, in the same order** — it exists so that "the tests pass" is a checkable claim when Actions is unavailable, and it is only worth having while it stays a faithful mirror. **Add a step to `ci.yml` and you must add it here too**, or the script quietly starts certifying less than it claims. Its `--help` prints the four things it deliberately does not check (chiefly: no clean checkout, so lockfile drift is invisible to it, and your platform is not `ubuntu-latest`); those are the only differences, and the summary reprints them after every run so a green local result is never mistaken for a green CI result.
